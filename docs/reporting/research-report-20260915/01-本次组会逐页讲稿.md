# 组会汇报：证据充分性感知的自适应检索进展

建议 8 页，约 12 分钟。选取当前约六成研究主题；本文件可直接用于制作幻灯片，每页提供上屏内容和口头讲稿。

## 第 1 页：研究问题与本次进展（1 分钟）

上屏内容：

- 问题：当前检索证据是否足够回答问题？
- 流程：Dense@5 → Hybrid@10 → Rerank@20。
- 前两个阶段判断 Stop/Continue，最后阶段强制终止。
- 本次：HotpotQA 风险与成本、2Wiki 检索上限。

讲稿：本阶段研究的是检索过程中什么时候可以停止。固定重检索会对所有问题付出相同成本，而简单的问题可能在较早阶段就已有足够证据。我先检验证据感知模型是否能判断充分性，再研究风险阈值，最后用第二个数据集区分模型误判和检索本身的限制。

## 第 2 页：判别能力的前期结论（1.5 分钟）

HotpotQA Phase 3A，Test 三种子均值及标准差：

| 模型 | Macro F1 | AUROC | 分类诊断 FSR |
|---|---:|---:|---:|
| Query+Stage | 0.5773 ± 0.0351 | 0.8207 ± 0.0081 | 84.66% ± 6.42% |
| Query+Evidence concat | 0.7523 ± 0.0169 | 0.9081 ± 0.0108 | 53.62% ± 5.59% |
| Query+Evidence score-aware | 0.7971 ± 0.0133 | 0.9246 ± 0.0072 | 45.15% ± 4.15% |

讲稿：证据输入带来稳定提升，按检索分数组织有限上下文优于直接截断拼接。但分类更好不代表阈值已经适合停止决策。辅助覆盖回归和 Hard Partial 采样也没有稳定的多种子增益。这促使我转向风险阈值研究。这里是全阶段分类诊断，下一页是实际到达阶段的顺序决策，不能直接相减声称 FSR 从 45% 降到 8%。

## 第 3 页：风险阈值如何确定（1 分钟）

上屏内容：

- Dev 分成 500 题校准集和 500 题策略选择集。
- 校准概率，再在 Dev 选择风险目标 10% 的保守阈值。
- 固定主策略阈值 0.93，然后评价 Test。
- 按 question ID 做配对 bootstrap，保留同一问题的阶段关联。

讲稿：我把概率校准和策略选择分开。阈值在 Dev 上固定，Test 只用于评价。FSR 统计的是到达的 Dense 和 Hybrid 阶段里，本应 Continue 却被 Stop 的比例。Rerank 是终止阶段，其证据不完整另算终止检索失败。

## 第 4 页：HotpotQA 质量与成本结果（2 分钟）

| 指标 | Fixed Heavy | 主策略 |
|---|---:|---:|
| Answer F1 | 0.5108 | 0.5104 |
| EM | 0.407 | 0.409 |
| 平均累计 chunks | 20.646 | 9.380 |
| 平均 Reranker 调用 | 1.000 | 0.207 |
| 汇总延迟 ms/题 | 587.79 | 347.67 |
| 可决策阶段 FSR | 0（无提前停止） | 8.45% |

讲稿：与全部执行重检索相比，主策略的 F1 点估计接近，chunks 减少约 54.6%，Reranker 调用减少 79.3%，组件测量汇总延迟减少约 40.9%。这里不是生产服务在线延迟。Fixed Heavy 的 FSR 为零只表示没有提前停止，不代表它总能取得充分证据或答对。

## 第 5 页：哪些结论成立，哪些还不成立（1.5 分钟）

上屏内容：

- F1 差值 95% CI：[-0.0193, 0.0185]，满足预设 -0.02 非劣界限。
- FSR 95% CI：[5.64%, 11.77%]；观测值低于 10%，区间未完全低于目标。
- 温度校准没有证明相对 raw 保守阈值的独立收益。
- 保守 5% 策略退化为全部到最终阶段。

讲稿：现有证据支持当前设置下的质量成本取舍，而不能保证风险始终低于 10%。温度校准本身也不能当作主要收益来源。更严格的风险目标可能牺牲全部提前停止收益。此外 HotpotQA Test 曾在前阶段查看，所以我推进第二个数据集的冻结评价，作为更严格的后续检验。

## 第 7 页：检索上限是另一类失败（2 分钟）

2Wiki dev_policy，2,000 题：

| 指标 | 结果 |
|---|---:|
| Dense 完整覆盖 | 32.20% |
| 累计 Hybrid 完整覆盖 | 35.05% |
| 最终完整覆盖 | 36.60% |
| 终止检索失败 TRFR | 63.40% |
| Dense 不完整 → 最终补齐 | 88/1,356 = 6.49% |
| Hybrid 不完整 → 最终补齐 | 31/1,299 = 2.39% |

讲稿：这是本周最值得讨论的发现。多数证据不完整的问题，继续当前检索链也无法补齐。因此控制器误停与检索上限必须分别分析。理想 Oracle 在证据充分时停止，否则继续，仍无法解决最终的 63.4%。这一上限只适用于当前冻结检索链，不是 2Wiki 数据集本身的理论上限。

## 备份：老师可能追问

**为什么人工审核 100% 一致还不能说标签完全正确？** 单人、分层抽样且审核主要参考已检索事实；它支持局部标注一致性，不能充当独立盲审或总体正确率。也不能证明 packed 输入保留所有事实。

**Coverage 辅助任务是否是有效创新？** 单个冻结 seed 有改善，但三种子均值没有稳定提升，论文应如实报告。

**低 FSR 会不会只是总预测 Continue？** 需要同时报告不必要升级率、平均 chunks、Reranker 调用及最终证据覆盖，后续 Judge 对照会展示这一问题。

**2Wiki 分数很高能否证明迁移？** 当前是域内训练及 Train 派生 Dev 评价，不能称为 HotpotQA 模型零样本迁移。

**能否看到 Heldout 后再改策略？** 当前一次性协议已冻结，按预设规则完整报告。若未来另做方法研究，需独立协议与评价安排。
